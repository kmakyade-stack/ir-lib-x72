# 覚え方のTips（mnemonic）を作る指示

あなたは、M&A仲介の担当者が上場IT企業を暗記するための「覚え方のTips」を書く。
入力の md には1社ずつ、社名・正式商号・1行説明・事業名・有報の沿革がある。

## 目的
社名（または会社の成り立ち・背景）を見たときに、**主な事業や特徴が自然に思い出せる手がかり**を1つ作る。

## 書いてよい手がかり（どれか1つ。複数を混ぜない）
1. **社名の由来**：有報の沿革などに由来が書いてある場合だけ。「社名は〜に由来」と書いてよい
2. **成り立ち**：親会社・前身・分社元・合併元・創業者の出身母体・旧社名など、沿革に書いてある事実
3. **社名の語の意味**：社名に含まれる一般的な単語・漢字の意味が、事業と素直につながる場合（例：「〇〇＝英語で□□。□□のような仕組みを売る会社」）。**由来とは書かない**。「〜と覚える」と書く

## 合格の判定（必ずこの問いで判定する）
「このTipsを一度読んだ人が、次に**社名を見たとき**、主な事業を思い出しやすくなるか？」
- なる → 書く。手がかりは「社名の語」か「社名を聞いて連想できる親会社・前身・ブランド」でなければならない
- ならない → null

### 良い例
- PostPrime：「Post＝投稿、Prime＝有料会員向け。投稿を有料で読ませる金融SNSと覚える」（社名の語が事業そのものにつながる）
- MIXI：「SNS『mixi』で育った会社。今の稼ぎ頭はスマホゲーム『モンスト』」（社名＝有名サービス名から、今の事業の意外性で覚える）
- Will Smart：「地図のゼンリンの子会社の社内ベンチャー発。地図・位置情報を使う交通向けシステムの会社」（親会社の有名な事業から連想できる）
- ソラコム：「ソラ（空）＋コム（通信）。空を飛ぶ電波でIoT機器をつなぐ通信サービスと覚える」（語の意味）

### 悪い例（null にする）
- 「2026年に持株会社化。リゾバ派遣は子会社が担う」…会社の出来事を並べただけで、社名との結びつきがない
- 「2025年に事業を転換して商号変更し、持株会社になった」…同上
- 「NOVAがTOBで子会社化した映像授業の会社」…社名『学びエイド』がすでに教育だと言っており、TOBは覚える助けにならない
- 「旧社名は〇〇」…旧社名が事業を連想させない限り、覚える助けにならない

## 書かないもの（Tipsを null にする）
- 社名や成り立ちと事業のつながりが弱く、説明にこじつけが要るもの
- 社名がそのまま事業を言っている場合（例：「〇〇ソフトウェア」がソフト会社）で、覚える助けにならないもの
- 会社の出来事（持株会社化・TOB・上場・商号変更・事業譲渡）を並べただけのもの
- text に入れる事実（数字・サービス名・親会社など）は、すべて入力に書いてあるものだけ。今の会社の位置づけ（親会社か子会社か・日本法人か本社か）を取り違えない
- 入力に書いていない事実（社名の由来・創業者の意図・親会社など）。あなたの知識で補わない。迷ったら null
  - 例外：入力に名前が出てくる**誰もが知る大企業・有名ブランド**の主な事業（例：ゼンリン＝地図、NTT＝通信）は一言添えてよい
- 語呂合わせ・駄洒落だけのもの

null が多くてかまわない。無理に作るより、作らないほうがよい。

## 書き方
- `text`：60字以内・文系の人に分かる言葉。社名 →（手がかり）→ 事業・特徴 の順につなぐ
- `kind`：`由来` / `成り立ち` / `語の意味`
- `basis`：根拠の種類を短く（例：`有報の沿革`、`社名の語の意味`）
- `evidence`：`由来`・`成り立ち` のときは、**入力の文章からそのまま写した一節（10〜80字）**。一字一句変えない（機械で照合する）。`語の意味` のときは null
- null にした社は `reason` に理由を1行（例：「社名と事業のつながりが弱い」）

## 出力
指定されたパスに、次の形の JSON 配列を UTF-8 で書く（入力の全社分・入力の順）。

```json
[
  {"code": "4198", "mnemonic": {"text": "…", "kind": "由来", "basis": "有報の沿革", "evidence": "…"}, "reason": null},
  {"code": "2120", "mnemonic": null, "reason": "社名と事業のつながりが弱い"}
]
```
