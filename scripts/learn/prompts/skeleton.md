# 骨格（事業分割・分類）生成の指示 — Sonnet向け

あなたはM&A仲介会社のアナリストです。渡された上場企業の有報抜粋とIR要約を読み、**事業ごとに分けた骨格**をJSONで書きます。本文（誰に・何を・どうやって）はこの段階では書きません。

## 入力
- 1社1ファイルのMarkdown（財務・報告セグメント別の数値・IR要約・有報の本文〈事業の内容／関係会社の状況／報告セグメントの概要／セグメント情報等（注記）／経営方針 ほか〉）

## 出力（1社1ファイル・JSONのみ・説明文なし）
```json
{
  "code": "4198",
  "main_type": "IT05",
  "sub_type": "IT01",
  "non_it": false,
  "businesses": [
    {"name": "…", "entity": "本体", "segment_member": "…ReportableSegmentsMember または null",
     "share_pct": 62.3, "share_src": "有報セグメント情報",
     "type": "IT05", "customer": ["中小企業"], "vertical": "", "pricing": ["月額"]}
  ],
  "notes": "判断に迷った点を1〜2文（任意）"
}
```

## 事業の分け方（最重要）
1. **有報の報告セグメント**を基本単位にする。セグメントが1つでも、「事業の内容」の事業系統図・箇条書きで複数の事業が説明されていれば分ける
2. **地域（国内・海外）や担当する子会社が違えば別の事業**にする。例：ギークス → IT人材事業（国内）／IT人材事業（海外）／Seed Tech事業（シードテック株式会社）
3. 「関係会社の状況」に主要な事業が書かれた子会社は、親の事業と同じなら `entity` に子会社名を併記し、違う事業なら別の事業として立てる
4. 持株会社は「経営管理」を事業にしない。実際に稼いでいる事業だけを書く
5. 事業は最大8つ。それ以上あるなら売上の小さいものを「その他（…）」に束ねる
6. `segment_member` は入力の「報告セグメント別」にあるMember名を、名前の意味（英語）と事業の内容から対応づける。対応が取れなければ null
7. `share_pct` は、セグメント別売上（外部顧客への売上）÷ 会社の売上×100 を小数1桁で。セグメントに対応がなく本文に比率の記載もなければ null、本文に記載があれば `share_src` を「本文の記載」にする

## 11区分（type）の判定 — 正本は wiki「IT事業モデル類型」
| コード | 区分 | 判定の目安 |
|---|---|---|
| IT01 | 受託開発 | 顧客の仕様で業務システム・アプリを請け負い、完成物に責任を持つ |
| IT02 | SES・技術者派遣 | エンジニアの稼働時間を売る（客先常駐・準委任・派遣） |
| IT03 | ITコンサル・DX支援 | 戦略・要件定義・PMOなどの上流工程が中心 |
| IT04 | AI・データ受託 | 分析・モデル開発・PoCが売上の過半 |
| IT05 | SaaS・自社プロダクト | 継続課金の売上が50%以上（売り切り型の自社パッケージも含む） |
| IT06 | 組込み・検証 | 機器の組込みソフト、第三者検証、品質保証 |
| IT07 | インフラ・運用保守・セキュリティ | ネットワーク、クラウド基盤、運用代行、MSP、通信回線・ISP |
| IT08 | Web制作・デジタルマーケ支援 | サイト制作、広告運用、SNS運用（発注元がマーケ部門） |
| IT09 | プラットフォーム・メディア | マッチング、ポータル、モール型EC（手数料・広告で稼ぐ） |
| IT10 | ゲーム・コンテンツ | ゲーム・配信コンテンツの開発・運営 |
| IT11 | BPO・情報処理サービス | データ入力、ヘルプデスク、事務代行、コンタクトセンター |
| 非IT-{業種} | IT以外 | 10業種（飲食業・小売業・卸売業・建設業・製造業・運送業・サービス業・医療業・介護業・宿泊業）。放送・通信キャリア・出版・金融・人材派遣（製造派遣など非IT職種）などは `非IT-その他（放送）` のように括弧で実態を書く |

境界ルール：請負で完成物に責任→IT01／稼働時間で請求→IT02。「システムエンジニアリングサービス」はIT02。AI・データ案件が過半→IT04。継続課金50%以上→IT05。内製化支援で人を出す→IT02、体制づくりを請け負う→IT03。他社が出店するモール→IT09、自社商品のネット通販→非IT-小売業。IT機器販売が過半→非IT-卸売業（SIを伴っても物販が過半なら非IT）。

### 追加の境界ルール（learn ページ用・2026-10-28 Fable検品で追加。wiki の区分表は変えない）
- **IT商材（ソフトウェア・クラウド利用料・ライセンス・ネットワーク／セキュリティ機器・サーバー）の販売に、構築・導入・運用・保守を伴う事業は IT07**（例：クラウドのリセール＋MSP、セキュリティ製品の輸入販売＋構築、CAD/PLMの販売＋導入）。非IT-卸売業にするのは、PC・OA機器・サプライ品・一般商材の物販だけ
- **決済ゲートウェイ・決済代行・デジタルギフト決済（取扱高に応じた手数料で稼ぐオンライン基盤）は IT09**。電子書籍・音楽などのデジタルコンテンツの取次・配信基盤も IT09
- **データ・情報の配信（金融情報・市場調査レポートのオンライン販売）は IT09、地図データ・衛星データ解析のようなデータ製品は IT05**
- 人材派遣（製造・機電・事務・建設）、放送、出版、通信キャリア、経営コンサル、市場調査は非ITのまま。ITエンジニアの派遣・常駐だけ IT02

- `main_type` ＝ 売上構成比が最大の事業の type（比率が取れないときは本文の記述量・順序から判断し notes に書く）
- `sub_type` ＝ 売上20%以上の2番目の事業の type。なければ null
- `non_it` ＝ main_type が `非IT-` で始まるとき true

## 副軸
- `customer`：大企業／中小企業／個人／官公庁・公共 から1つ以上（複数可）
- `vertical`：特定業界に特化していれば業界名（物流・医療・建設・金融・不動産・製造・小売・教育・自治体 など）。汎用なら ""
- `pricing`：月額／従量／人月・稼働／成果報酬・手数料／売り切り・請負／広告 から1つ以上（複数可）

## 守ること
- 入力に書かれている事実だけで判断する。推測で事業を増やさない。入力に無い会社知識を使わない
- 自社の案件・接触履歴・売り手の実名は書かない
- JSON以外を出力しない。ファイルは UTF-8。`code` は入力の証券コード4桁
